\begin{abstract}
\noindent
Hanzo cloud's \texttt{/v1/graph} keeps an organization's entities and relations
in one append-only table of assertions. An assertion states that an entity
stands in a relation to a value from an instant \texttt{at}, optionally until an
instant \texttt{until}, with a source, evidence, the filing identity and a
confidence. The server derives a \emph{knowable} instant, the later of the
filer's own claim and the write. Nothing is updated in place, a retraction is an
assertion, and the only deletion is erasure of a data subject. Every read takes
a valid instant, \texttt{as\_of}, and a transaction instant,
\texttt{as\_known}; versions of a statement correct each other only when one was
learned later; a relation holds one value or several, as the organization
declares; and type, domain, range and cardinality are assertions in the same
table, checked as known when the checked row became knowable. We state the
resolution rule and its properties, among them that an answer as known at an
instant is unchanged by every later write except erasure. We describe the
operations built on it: a diff between two bitemporal points, shortest paths
with a confidence product, erasure with a receipt that verifies against an
audit trail and is refused under litigation hold, deterministic Louvain
communities, and a map-reduce answer that refuses uncited claims.

On the \res{cron/n} covered CronQuestions test questions, answered by one query
plan, a dictionary control, semantica~0.7.0 and the store all score
\res{cron/kg/all}\% Hits@1 and give the same answer to every question, whether
history is filed at one instant or as it happened. The store's median call takes
\res{cron/wire/p50}\,ms and semantica's \res{cron/sem/p50}\,ms. The first run of
the same lane scored \res{cron/first/wire/all}\%, and \res{cron/first/wire/se}\%
on point-in-time questions, because the single \texttt{as\_of} of that version
bounded transaction time and a retraction ended every value of its pair; the
harness then found two defects in the correction. On LongMemEval-S, a retrieval
engine in the same memory stack, which does not use this store, raises session
ALL@5 from \res{lme/all/cosfive} to \res{lme/all/engfive} over cosine similarity
on the same vectors, with no tuning on that benchmark.
\end{abstract}
