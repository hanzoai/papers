\section{Related work}
\label{sec:related}

Hosted sandbox platforms publish cold-start and minimum-memory figures for the
container tier: E2B under 200\,ms with a 512\,MB minimum~\cite{e2b}, Modal
around a second with a 128\,MB minimum~\cite{modal}, and Cloudflare Workers
1--3\,s for a container with 256\,MB~\cite{cfworkers}. These are the numbers that
set the industry estimate this paper takes apart, and \S\ref{sec:isolation}
measures the same primitive rather than a cheaper one in order to compare
honestly.

The in-process tier has a long lineage that agent platforms have mostly not
drawn on. V8 isolates as a multi-tenant unit are the basis of edge function
platforms~\cite{cfworkers}; WebAssembly's capability model gives a deny-by-default
boundary at a fraction of a container's cost~\cite{wasm}; and pure-Go
implementations of all three runtimes measured here~\cite{wazero,goja,gpython}
make the tier available without CGO or a second process. The contribution of
\S\ref{sec:code} is not the runtimes but the measurement that all three sit in
the microseconds, which is what makes the three-rung ladder in
\S\ref{sec:isolation} a practical policy rather than a taxonomy.

The residency argument is the agent-scale case of the tenant-scale one made
in~\cite{unifiedtenant}, where a per-tenant SQLite file was measured at
${\approx}0.25$\,MB resident and the conclusion was that memory scales with
concurrency rather than registrations. Green threads as a cheap concurrency unit
predate all of this and the goroutine implementation's growable
stacks~\cite{gostack} are what make the \rGoPer{}-byte figure possible.

\section{Conclusion}
\label{sec:conclusion}

An agent is not a process, and costing it as one inflates the estimate by
roughly five orders of magnitude. Measured separately on one laptop: state at
rest is \rFleetPer{}\,bytes, execution at rest is \rGoPer{}\,bytes, and isolation
is \rVeight{}--\rOci{}\,ms depending on which boundary the workload actually
needs.

The practical consequence is a policy rather than a product. Take the cheapest
rung the threat model permits; keep dormant agents as rows and rehydrate them in
\rFleetResume{}\,ms rather than holding loops open; pool the expensive boundary
so that a fleet pays \rPooled{}\,ms in steady state instead of \rOci{}\,ms per
call; and size memory against what the agents \emph{hold}, since the primitives
holding them contribute nothing measurable.

The result we would most like to see contested is the one we flagged hardest:
\rGoPer{}\,bytes is the residency of an agent that holds nothing, and a fleet of
agents that hold something will be dominated by that something. The measurement
says the platform overhead is not the problem. It does not say there is no
problem.

\section*{Reproducing}

The scripts are in \texttt{hanzoai/cloud} under \texttt{bench/}, one directory
per measurement, and each prints the table it produced:

\begin{lstlisting}[language=bash]
node fleet/fleet.mjs /tmp/fleet     # state at rest
go build -o /tmp/goro . && /tmp/goro  # execution at rest, and the runtimes
node sandbox/sandbox.mjs            # isolation (needs a container runtime)
node pricing/pricing.mjs            # rates
\end{lstlisting}
